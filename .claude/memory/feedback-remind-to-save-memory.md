2026-11-09 用户要求：「学习到的新知识，需要往记忆体系保存的，提醒我保存」。用户的用词是「**及时更新**记忆」，所以要覆盖两侧：**新增**和**修正/淘汰**。

**Why:** 用户要掌控记忆库里到底有什么——写进去的东西会被后续会话当成事实反复引用，错误或过时的记忆代价很高（比没有记忆更糟）；而当场由用户点头确认，还能顺带纠正措辞。

**How to apply:**

1. **新增**：在一轮对话里发现**非代码可推导**的新事实（用户纠正的做法、环境坑、配置为何这么写、某个决定的原因）时，在回复末尾用一句话点出：「这条值得存记忆：<一句话>，要我写进 `.claude/memory/` 吗？」
2. **更新**：读到的记忆和当前代码/配置/运行态对不上时，**当场指出**并提议改哪一条，例如「`project-env-snapshot` 里 consumer 还写 8002，但你现在已经统一到 8006 了，要我更新吗？」——不要沿用旧值继续干活，也不要默默改掉不吭声。
3. **淘汰**：某条记忆被证伪、或所述对象已删除（文件/配置/功能没了）时，提醒删除该条并同步 `MEMORY.md` 索引。
4. 等用户确认再写/改/删；用户明确说「记一下/存进记忆/更新一下」时直接执行。
5. 不要事无巨细都提醒——代码结构、git 历史、`CLAUDE.md`/`docs` 已写的内容不提醒。
6. 一次最多提醒 1~2 条最有价值的，避免刷屏。

**带日期的快照类记忆**（如 `project-env-snapshot-2026-11-09`、外部 config 生效差异表）最容易过时，引用前先核对，发现漂移就按第 2 条处理。
